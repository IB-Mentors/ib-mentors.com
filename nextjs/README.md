# ib-mentors.com in Next.js

A 1:1 rebuild of the IB Mentors Framer site (`amusing-environment-470649.framer.app`) in Next.js 16 (App Router),
React 19, CSS Modules and `motion`: same layout at every width, same Japanese copy, same images and animations. It
replaces the static Framer mirror in the repo root (`export.sh` + `scripts/*.py`) and carries everything that mirror
adds on top of Framer (tags, metadata, JSON-LD, llms.txt, the "Site by Kelin Studio" credit). **It is not live yet**:
see "Going live".

```bash
npm install
npm run dev          # http://localhost:3410
npm run typecheck
npm run lint
npm run build        # NEXT_DIST_DIR=.next-build npm run build to build beside a running dev server
```

## Layout

| Path | What |
|---|---|
| `src/app/**` | Routes, one file each, URLs exactly as Framer's (no trailing slash). CMS detail routes use `generateStaticParams` with the Framer slugs; any other slug is a 404. `not-found.tsx` is Framer's styled 404 (status 404, noindex). |
| `src/app/api/contact` | One endpoint for the three Framer forms (see "Forms and leads"). |
| `src/app/sitemap.xml`, `robots.txt` | Same URLs as Framer's sitemap and the mirror's robots.txt, built from `src/content/`. |
| `src/components/shell/` | `Page` frame, `Navigation`, `Footer`, `SiteCredit` ("Site by Kelin Studio", as production carries it) |
| `src/components/ui/`, `src/components/cards/` | Shared Framer components (`Hero Button` variants, `Load More Button`, `Course Card`, `Team Card`) |
| `src/components/<page>/` | Pages and their sections (`home`, `courses`, `teams`, `blogs`, `faq`, `contact`, `become-mentor`, `not-found`) |
| `src/content/{courses,blogs,teams}.ts` | The Framer CMS collections, generated by `python3 qa/extract-content.py` |
| `src/lib/measurement.ts`, `src/components/measurement/` | Tags, host guard, click-ID capture, events, JSON-LD (see "Measurement") |
| `src/lib/meta.ts`, `src/lib/seo-data.ts` | Titles, descriptions, canonicals, robots, Open Graph / Twitter: a snapshot of what the mirror serves (`python3 qa/gen-seo.py`), with a derived fallback for new CMS entries |
| `src/lib/leads.ts` | Lead validation helpers and delivery (Resend and/or webhook) |
| `src/app/{tokens,presets,fonts}.css`, `public/framer/`, `public/fonts/` | Framer colour tokens (by token id), text presets as `.p-<id>`, self-hosted fonts, every image (`python3 qa/gen.py`) |
| `public/{ads.txt,llms.txt,SocialPreview.png}` | Copied byte for byte from the mirror |
| `vercel.json` | Pins the framework to Next.js, `trailingSlash: false`, www to apex 308 (same as the repo-root one) |

Breakpoints are this Framer project's own: desktop `>= 1380px`, tablet `768..1379.98px`, phone `<= 767.98px`.
`docs/BUILD-BRIEF.md` is the brief the pages were built to.

## Measurement

Everything production (the mirror's `scripts/inject-*.py`) carries, same IDs, in the house pattern of oglabs.io and
www.kelin.studio. Details and the reasoning live in the comments of `src/lib/measurement.ts`.

| What | ID | How |
|---|---|---|
| GA4 | `G-13MKYG4YL9` | gtag.js, configured inline. `send_page_view` on; enhanced measurement reports App Router navigations. |
| Google Tag Manager | `GTM-PBHMLWMQ` | The site's own container in the Kelin Studio GTM account. On 18 Oct 2026 `gtm.js?id=GTM-PBHMLWMQ` answered 200 with published version 1 and **no tags**, so it is loaded (ready for tags added by a GTM publish) and GA4 stays direct. If a GA4 tag for `G-13MKYG4YL9` is ever added to the container, empty `GA4_MEASUREMENT_ID` in the same change or page views count twice. |
| AdSense | `ca-pub-8631844190242419` | `adsbygoogle.js` in `<head>` on every page, not host-gated (the reviewer reads raw HTML). `public/ads.txt`. |
| Cloudflare Web Analytics | token `92f77c51d67f4f1c815fe7d9113ca7a3` | Manual beacon after load (the DNS record is grey-cloud, so Cloudflare cannot inject it). |
| Google Ads | none | No Google Ads account for IB Mentors yet: `GOOGLE_ADS_TAG_ID` + `ADS_CONVERSION_LABELS` are ready, empty. |
| Search Console | `ib-mentors.com` domain property | DNS-verified, nothing in code. The mirror has no `google-site-verification` meta, so neither does this. |

- **Host guard** (`ibm-guard`, first inline script): only `ib-mentors.com` / `www.ib-mentors.com` are measured
  (`window.__msMeasure`). On localhost and preview hosts gtag is never configured, GTM and the beacon never load, and
  the console says so once. It also strips paid-looking UTMs that arrive without a click ID.
- **Click IDs**: `gclid`, `wbraid`, `gbraid`, `fbclid`, `ttclid`, `msclkid`, `li_fat_id`, `rdt_cid` plus UTMs, first and
  last touch, kept 90 days in `localStorage` (`ms_attr_v1`). `attributionParams()` flattens them (`click_id`,
  `ad_source`, `utm_campaign`, `utm_term`, `utm_content`, `landing_page`, `first_source`, `first_landing_page`); they
  ride on every conversion event and on every lead payload.
- **Events**: `generate_lead` (form submit, only after `/api/contact` answered 2xx), `contact_click` (LINE, mailto,
  tel) and `cta_click` (internal links to /contact), from one delegated listener (`MeasurementListener`).
- **Placement**: the two external loaders sit in `<head>`; the inline scripts (guard, GTM, gtag init, beacon) are the
  first children of `<body>`. adsbygoogle.js inserts its `show_ads_impl` script before the first `<script>` of the
  document; inline scripts in `<head>` are hydrated by position, so that node was matched against `ibm-guard` and every
  route logged a hydration mismatch. Script ids are prefixed `ibm-` (an id like `clarity` shadows a window global).
- **JSON-LD** (`JsonLd.tsx`): the mirror's blocks per route (EducationalOrganization + WebSite on `/`, Course,
  BlogPosting, Person + BreadcrumbList on detail pages, CollectionPage, ContactPage), plus `parentOrganization`
  Kelin Studio and `founder` Edward Zhang on the organization node, and FAQPage on `/faq` (see below).

## Forms and leads

`/contact`, `/faq` ("Contact Section") and `/become-mentor` post JSON to `/api/contact`:
`{ form, page, fields: { Name, "Email ", Message, "Phone number", Location }, honeypot, attribution, referrer }`
(Framer's own field names, trailing space included). The route validates (JSON body, a name, a valid email; a filled
honeypot is accepted with 200 and dropped), attaches the attribution and user agent, and delivers:

| Answer | When |
|---|---|
| 200 | delivered (webhook and/or Resend) |
| 400 | invalid body, no name or no valid email |
| 502 | delivery configured but every attempt failed |
| 503 | nothing configured: the form shows its Error state, so a lead is never dropped silently |

The form shows Loading, then "Thank you" (2xx, and only then `generate_lead`) or "Something went wrong"; from the
error state the visitor can submit again. **Never submit a form on the live Framer site**: every submission there is a
real lead email. Test with Playwright `page.route("**/api/contact", ...)`, or a local webhook (below).

## Env

| Var | Why |
|---|---|
| `RESEND_API_KEY` + `LEADS_TO` (+ `LEADS_FROM`, default `IBメンター website <website@mail.kelin.studio>`) | Each submission is emailed to `LEADS_TO` (comma separated) with `reply_to` the visitor. |
| `LEADS_WEBHOOK_URL` + `LEADS_WEBHOOK_SECRET` | Optional, tried first: each submission is POSTed as JSON with `Authorization: Bearer <secret>`. If it fails, Resend is still tried. |
| `SITE_NOINDEX=1` | Preview hosts: `noindex` meta and a disallow-all `robots.txt`. |
| `NEXT_DIST_DIR` | Build output folder (default `.next`), so a production build can run beside the dev server. |

With neither delivery pair set, `/api/contact` answers 503 (checked locally with a real POST).

## Parity checks

Reference material is regenerated locally (git-ignored):

```bash
cd qa/framer && cat all-urls.txt | xargs -P 8 -n 1 bash ../fetch-page.sh && cd ../..   # Framer SSR HTML
python3 qa/gen.py                 # modules (prettified), tokens, presets, fonts, images
python3 qa/extract-content.py     # src/content/*.ts
python3 qa/gen-seo.py             # src/lib/seo-data.ts from the mirror in the repo root
node qa/dump.mjs all              # computed-style dumps into qa/ref/
```

Checks (Playwright resolved from the Fruition monorepo, see the scripts):

```bash
node qa/heights.mjs                                    # every route, page height live vs ours, 1440/1000/390
node qa/compare.mjs /courses @page 1440,1000,390        # whole page in 900px bands, live left / ours right
node qa/compare.mjs / "Hero Section" 1440,390           # one named Framer section
node qa/links.mjs                                      # internal links 200, console errors, broken images (ours)
node qa/seo-check.mjs                                  # head tags + JSON-LD types per route: https://ib-mentors.com vs ours
NEXT_DIST_DIR=.next-build npm run build && NEXT_DIST_DIR=.next-build npx next start -p 3411 &
node qa/tags-check.mjs 3411                            # tags + events on a production build, see below
```

`OURS_URL` (default `http://localhost:3410`), `LIVE_URL` and `PROD_URL` point the scripts elsewhere.
`qa/tags-check.mjs` maps `ib-mentors.com` to the local server in Chromium (`--host-resolver-rules`), so the real host
guard measures, and fulfills every GA4 `/g/collect`, Cloudflare RUM and AdSense ad request locally: nothing reaches
the real properties. It checks gtag/GTM/AdSense/beacon load, one `page_view`, click-ID capture, `generate_lead` with
the click ID on a mocked 200, the error state and no event on a 503, retry after an error, and silence on localhost.
For an end-to-end lead, start the production server with `LEADS_WEBHOOK_URL=http://127.0.0.1:<port>` pointing at a
local capture server.

State on 18 Oct 2026: heights 69/69 (23 routes x 3 widths, dev and production build); links: all internal links 200,
every Framer sitemap URL exists, no console errors; head tags identical to production on 22/23 routes (the 23rd is
`/404`, see below); tags-check all green.

## Intended differences from the Framer site

- The "Site by Kelin Studio" band under the footer (production carries it; the qa scripts hide `#ibm-site-credit`).
  It makes every page 39px taller than Framer's.
- The tags, metadata and JSON-LD above (production carries them). Framer's own analytics, search index metas and the
  "Made in Framer" badge are not rebuilt.
- `/faq` server-renders all eight answers (Framer renders two of eight until clicked), so it carries FAQPage JSON-LD:
  the mirror's own rule (`inject-jsonld.py`: emit only when every answer is in the HTML) now passes.
- The organization JSON-LD names Kelin Studio as `parentOrganization` and Edward Zhang as `founder`.
- `/404` and unknown URLs answer status 404 (the mirror serves `/404` with 200).
- Forms post to our own endpoint instead of Framer's form service, and can be resubmitted after an error.
- Two Go Back buttons exist (`src/components/blogs/GoBackButton.tsx`, label "Go Back " with Framer's trailing space and
  two V2 instances; `src/components/courses/GoBackButton.tsx`, label "Go Back"); both are verified against their pages,
  so they were not merged.
- Copy is verbatim, including the Framer source's known issues (repo-root README "Known issues in the Framer source":
  the footer `mailto: info@elearning.com`, the crossed LINE/Instagram links, the corrupted characters in some posts,
  the template options in the /become-mentor selects).

## Going live

Each step is a production change. DNS does not change: `ib-mentors.com` (A, grey-cloud at Cloudflare, zone in the
Kelin Studio Cloudflare account) and `www` (CNAME to Vercel) already point at the Vercel project `ib-mentors.com`
(`prj_anT7wXj7alaYRJrrko7xJ7c4WmJg`, team `edwardzehuazhangs-projects`), which today serves the repo root as a static
site (framework "Other", no Root Directory). The cutover only changes what that project builds.

1. **Lead delivery.** On the Vercel project set `RESEND_API_KEY` + `LEADS_TO` (and `LEADS_FROM` if the default sender
   domain is not verified in that Resend account), and/or `LEADS_WEBHOOK_URL` + `LEADS_WEBHOOK_SECRET`, for Production
   and Preview. Without them every form shows its error state.
2. **Merge** `nextjs-rebuild` into `main` (the `nextjs/` folder only adds files; the mirror keeps serving until step 3).
3. **Switch the project**: Vercel > `ib-mentors.com` > Settings > Build and Deployment: Root Directory `nextjs`,
   Framework Preset Next.js (also pinned by `nextjs/vercel.json`), build/output/install commands default, Node 24.x.
   Save, then Deployments > Redeploy the latest `main` commit without the build cache. Or with the CLI:
   `vercel api "/v9/projects/prj_anT7wXj7alaYRJrrko7xJ7c4WmJg?teamId=team_JQoxPCHAFHTF2kAHrdGRkxPV" --method PATCH --input <(echo '{"rootDirectory":"nextjs","framework":"nextjs"}')`.
4. **Stop the Framer export**: `gh workflow disable framer-export.yml -R IB-Mentors/ib-mentors.com`. It would keep
   committing a new mirror to the repo root (and starting production builds) on every Framer publish. From now on a
   CMS change is `python3 qa/extract-content.py` (plus `qa/gen-seo.py` for new metadata) and a commit.
5. **Smoke test production** (before the switch, run `node qa/seo-check.mjs` with `OURS_URL` set to the new
   deployment's URL so the mirror is still the comparison): `OURS_URL=https://ib-mentors.com node qa/heights.mjs` and
   `node qa/links.mjs` with the same `OURS_URL`; `curl -sI https://www.ib-mentors.com/courses` is a 308 to the apex; `/sitemap.xml`,
   `/robots.txt`, `/llms.txt`, `/ads.txt` answer 200 and `/nope` 404; GA4 Realtime shows your visit; one real form
   submission arrives (then reply to it so nobody chases it).
6. **Search Console**: submit `https://ib-mentors.com/sitemap.xml` again and inspect `/` and `/faq` (FAQPage) with
   URL Inspection.

**Rollback** (minutes, no DNS change): Vercel > `ib-mentors.com` > Deployments, pick the last deployment built from
the repo root and "Promote to Production" (instant). Then make it stick: Settings > Build and Deployment, Root
Directory empty and Framework Preset "Other" (`--input '{"rootDirectory":null,"framework":null}'` with the same CLI
call), and `gh workflow enable framer-export.yml -R IB-Mentors/ib-mentors.com`. The mirror and its repo-root
`vercel.json` stay in the repo root untouched, so the next build of `main` serves it again. Only if the Vercel
project itself is lost: point `ib-mentors.com` (A `216.198.79.1`) and `www` (CNAME to the project's
`*.vercel-dns-017.com` target shown under Settings > Domains) at the replacement project, both grey-cloud in Cloudflare.
